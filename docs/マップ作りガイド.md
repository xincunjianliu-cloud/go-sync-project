# マップ作りガイド

このゲームのマップは **Tiled** で作ります。この資料だけ見れば、マップ作りのすべてが分かるようにしてあります。

---

## 0. 最初に1回だけ:Tiledでプロジェクトを開く

1. Tiledを起動する
2. 上のメニューの「**プロジェクト**」→「**プロジェクトを開く...**」→ `rpg.tiled-project` を選ぶ
   - 作業フォルダ(2章)の中にある
3. 左に「プロジェクト」パネルが出れば成功(出ないときは「表示」→「ビューとツールバー」→「プロジェクト」にチェック)

一度開けば、次からはTiledを起動すると自動で開きます。

これで、次のことができるようになります。
- 左にマップとタイルセットの一覧が出る
- しかけ(宝箱など)を**一覧から選んで**作れる(5章)
- **F5** で、今開いているマップから試し遊びできる(7章)

---

## 1. フォルダ

```
作業フォルダ\               (PCによって rpg または go-sync-project)
  rpg.tiled-project         Tiledのプロジェクト(しかけの一覧・F5)
  assets\maps\              マップ(.tmj)
  assets\tilesets\          タイルセット(.tsx)
  assets\images\tiles\      タイル画像(.png)
  docs\                     この資料・作業の手順・ほかのPCの準備・シナリオ記述ルール
```

---

## 2. ほかのPCとのやり取り(GitHub Desktop)

GitHubが「みんなの共通の置き場所」になり、各PCはそこから受け取り(Pull)、そこへ送ります(Push)。新しいPCの準備と、前のマップの移し方は `docs\ほかのPCの準備.md` にあります。

| | |
|---|---|
| 作業を始める前 | **「Fetch origin」→「Pull origin」**(ほかのPCの変更を取り込む) |
| 作業が終わったら | 左に変更が出る → 下に一言書いて **「Commit to main」→「Push origin」** |

- 各PCに**同じ中身のフォルダが1つずつ**あり、Push / Pull したときだけ中身がそろいます
- Pushすると、GitHubでチェック(8章)が自動で走り、問題がなければWeb版に公開されます
- 2台で同じマップを直してしまうと、Pull のときに GitHub Desktop が「conflict(ぶつかり)」と知らせてくれます。マップのファイルは2つを混ぜられないので、**どちらの版を残すか決めて**、残さない方の変更はもう一度直し直してください(困ったらClaudeに聞く)
- セーブデータと設定(`settings.json`)だけはPCごとに別々です

### 守ること

- **同じマップを2台以上で同時に直さない**(違うマップなら同時に直してよい)
- 直したら、すぐ Push してほかのPCに届ける
- **Pull する前に、Tiledで開いているマップを保存して閉じる**。開いたままだと、Tiledが古い中身を持ったままになり、次に保存したときに相手の変更を上書きして消してしまう
- Tiledに「ファイルが変更されました」と出たら、「**再読み込み**」を選ぶ

## 3. 新しいマップを作る

### 3-1. マップを作る

1. **作る**(作業フォルダのターミナル):
   ```
   go run ./tools/newmap dungeon_a
   ```
   `assets\maps\dungeon_a.tmj` ができる(120×40マス)。大きさを変えるときは後ろに横と縦のマス数を付ける(例: `go run ./tools/newmap dungeon_a 60 40`)
   - 名前は**英小文字**(数字と `_` も可)。公開した後は変えない(セーブデータに残るため)
   - 中身:タイルセット全部、レイヤー(床・`kabe`・`events`・`player`・主人公より上・`collision`)、マップ設定のクラス、着地点 `start_point`
2. **地名を書く**(Tiled):開いて「マップ」→「マッププロパティ...」→「地名」(曲や戦闘背景もここ。6章)
3. **描く**:タイルセットのパネルからタイルを選んで描く。しかけは5章。レイヤーは増やしても名前を変えてもよい(4章の決まった名前以外)
4. **ほかのマップとつなぐ**:3-3(つなぐまでは8章のチェックで止まる)
5. 保存して、**F5** で試し遊びする(7章)

### 3-2. 新しいタイル画像(タイルセット)を追加する

1. **画像を置く**(エクスプローラー):PNGを `assets\images\tiles` にコピー(名前は英小文字。例: `forest.png`)
2. **タイルセットを作る**(Tiled):「ファイル」→「新規」→「新しいタイルセット...」
   - 名前:`forest`/種類:「**タイルセット画像を元にする**」/「マップに埋め込む」:**チェックを外す**/画像:1のPNG/タイルの幅・高さ:**32**
   - 保存先は `assets\tilesets`(`forest.tsx` ができる)
3. **マップで使う**:マップを開いて「マップ」→「**外部タイルセットを追加...**」→ `forest.tsx`
4. 必要なら:
   - **通れないタイル**:`forest.tsx` でタイルを選び、プロパティの「+」→ 名前 `wall`、種類 bool → チェックを入れる
   - **動くタイル**:`forest.tsx` でタイルを選び、「アニメーションエディタ」(フィルムのアイコン)でコマを並べる(数字は1コマの長さ。ミリ秒)。マップに置いたそのタイルが、ゲームでも同じ速さで動く
5. 画像に描き足すときは、**横幅は変えずに下に行を足す**。**同じファイル名のまま上書き保存**し(`school (2).png` のような別名にしない)、Tiledでその `.tsx` を開いて保存し直す(画像の大きさが `.tsx` に記録される)

### 3-3. マップとマップをドアでつなぐ

例:`school_1` から `dungeon_a` へ行けるようにする
1. `dungeon_a` の `events` に四角を描き、クラス「**着地点**」、上の「名前」欄に `入口`
2. `school_1` のドアにしたい場所の `events` に四角を描き、クラス「**ドア**」→ 行き先マップ `dungeon_a.tmj`、着地点 `入口`
3. 帰り道も同じように作る(`school_1` に着地点、`dungeon_a` にドア)
4. F5 で行き来できるか確かめる(どこからもつながっていないマップは、8章のチェックで止まる)

## 4. レイヤー

| レイヤー名 | 役割 |
|---|---|
| `events`(`events` で始まる名前ならよい) | **しかけを置く**。何枚あってもよい |
| `collision` | 四角を置くと**通れない**(水など)。名札は要らない |
| `player` | 何も置かない。主人公を描く重なり順の位置 |
| `kabe` | ここに描いたタイルは**通れない** |
| クラスを「**レバーで出るレイヤー**」にしたタイルレイヤー | 描いた絵が**レバーを上げたときだけ**出る(机の橋など) |
| そのほかの名前 | 見た目だけ |

- Tiledで**非表示**(目のアイコン)にしたレイヤーは、ゲームでも**描かれません**。当たり判定は残るので、`kabe` レイヤーを非表示にすると「見えない壁」になります
- レイヤーの**不透明度**もゲームに反映されます
- レイヤーを**グループ(フォルダ)**にまとめてもかまいません。グループを非表示にすると中も非表示になります

---

## 5. しかけを置く

1. `events` レイヤーを選ぶ
2. 四角を置く(「四角形を挿入」ツール)
3. 左のプロパティで「**クラス**」を一覧から選ぶ
4. 出てきた欄を埋める(アイテム・敵・曲などは**一覧から選ぶ**)

### クラスの一覧

| クラス | 欄 | 何ができるか |
|---|---|---|
| **ドア** | 行き先マップ(ファイルを選ぶ)、着地点、倒すまで通れないボス | 触れると「▼ 進む」と出て、別のマップへ移動する |
| **着地点** | 向き。**名前欄**に名前を書く | ドアで来たときに立つ場所。ドアの「着地点」と同じ名前にする |
| **会話** | セリフ、会話データ(一覧)、2回目からのセリフ、目的地の名前・順番、達成するボス | 話しかける・調べる。セリフは `｜` で区切るとページが分かれる。セリフも会話データも空なら「調べるとなにかあるかもしれない」 |
| **宝箱** | 中身(一覧) | 開けるとアイテムが手に入る |
| **鍵の宝箱** | 鍵の名前 | 鍵が手に入る |
| **鍵の壁** | 必要な鍵(カンマで複数) | 鍵がそろうと開く |
| **レバー** | レバーの名前、一度きり | 上げ下げできる |
| **レバーの壁** | レバーの名前、見た目だけ | レバーを上げると開いて通れる。「見た目だけ」にすると、通れないまま見た目だけ変わる |
| **ブロック** | ブロックの名前 | 押して動かせる |
| **ブロック置き場** | 置き場の名前 | ブロックを乗せる場所 |
| **ブロック扉** | 置き場の名前(カンマで複数) | 全部の置き場にブロックが乗ると開く |
| **イベント** | セリフ、会話データ(一覧)、ボス戦、歩く道順、すぐ始める、目的地の名前・順番 | 通り抜けると起きる。ボス戦を選ぶとボス戦の入口になる |
| **ボス** | ボス番号、目的地の名前 | フィールドに立つボス。倒すと消える |
| **敵が出る場所** | 出る敵(一覧から複数選べる)、一度に出る最大数 | この中を歩くと敵に出会う |
| **暗い場所** | 明るくするレバー | 暗くなる。レバーを上げると明るくなる |

### 補足

- **歩く道順**:`up`・`down`・`left`・`right` + 距離(ピクセル)をカンマでつなぐ(例: `up120,right64`)
- **会話データ**:スプレッドシートに書いた会話のidを一覧から選ぶ。選ぶとセリフの欄より優先される。新しい会話が一覧に出ないときは、`go run ./tools/update` を打ってからTiledを開き直す
- **目的地**:画面に「次はここ」と出す機能。目的地の名前は全マップで重ならないようにする。順番は小さい数ほど先
- **レバー・ブロック・置き場の名前**は、つながる相手と**1文字も違わず**同じにする
- 宝箱・ブロック・レバー壁などは、**消して作り直さない**(セーブの記録がずれることがある)

### 例:水と机の橋

| 場所 | 作り方 |
|---|---|
| 机の橋(レバーで渡れる) | 「レバーの壁」を置く + 「レバーで出るレイヤー」に机を描く |
| ただの水(ずっと通れない) | 水を描いて、`collision` に四角を置く |
| レバーで見た目が変わる水 | 「レバーの壁」で「見た目だけ」にチェック + 「レバーで出るレイヤー」に変わった後の水を描く |

## 6. マップ設定

マップそのもののプロパティで、クラスを「**マップ設定**」にします(「マップ」→「マッププロパティ」)。

| 欄 | 意味 | 何も選ばないと |
|---|---|---|
| 地名 | ドアで入ったとき左上に出る。セーブ画面にも出る(バトル後は出ない) | ファイル名が出る |
| 曲 | 歩いているときの曲(一覧) | フィールド1 |
| 戦闘背景 | 戦闘の背景(一覧) | いつもの背景 |
| 入ると全回復 | 入るたびに全回復する(バトル後は回復しない) | 回復しない |

---

## 7. 試し遊び(F5)

Tiledで **F5** を押すと、保存してから、**今開いているマップから**ゲームが始まります(ニューゲームの状態)。
- 最初の1回は準備に時間がかかります(準備が済んだPCは10〜30秒、新しく準備したPCは**1〜2分**)。2回目からは速くなります
- F5で何も起きないときは、上のツールバーの「コマンド」ボタン横の▼ →「このマップで遊ぶ」
- 立つ場所:`start_point` という着地点があればそこ、無ければ最初の着地点、それも無ければマップの真ん中
---

## 8. 自動チェック

次のミスは、`go test ./...` で見つかり、公開が止まります。GitHub Desktopで Push したときはGitHubで自動で調べられ、**止まったときはGitHubの登録メールアドレスに「失敗しました」というメールが届きます**(内容が分からないときはClaudeに見せてください)。直してから、もう一度 Push してください。

- タイルセットの付け方の間違い、タイル番号のずれ、画像の大きさのずれ
- ドアの行き先・着地点が無い、どこからもドアでつながっていないマップ
- レバー・鍵・ブロックの名前のずれ
- 宝箱の中身・敵・曲・戦闘背景・会話データ・ボス番号の間違い
- 名札の名前の綴り間違い、決まった言葉(`event_～`)の書き間違い
- `collision` の四角が机の橋をふさいでいる
- しかけを `events` 以外のレイヤーに置いた
- 無限マップ、テンプレートの使用、タイルを置くオブジェクトの使用、タイルの大きさが32×32でない
- アニメーションのコマがタイルセットの外を指している、コマの長さが0
- レイヤーのずらし・視差・色合い、画像レイヤー、オブジェクトの回転、`collision` の楕円、タイルの当たり判定エディタの形、タイルのずらし

---

## 9. やってはいけないこと

- ❌ 公開した後にマップのファイル名を変える(どうしても変えるときは `save_migrate.go` に旧→新を足す)
- ❌ タイル画像の横幅を変える
- ❌ 水などマップ全体に敷くタイルに `wall` を付ける(床の上まで通れなくなる)
- ❌ テンプレート(.tx)・無限マップ・「タイルを挿入」で置くオブジェクトを使う(絵はタイルレイヤーに描く)
- ❌ レイヤーのずらし(オフセット)・視差・色合い(ティント)、画像レイヤー、オブジェクトの回転、`collision` の楕円を使う
- ❌ タイルの当たり判定エディタで形を描く(通れなくしたいタイルには `wall`=`true` を付ける)
- ❌ Tiledの「カスタムタイプエディタ」でクラスや一覧を書き換える(`rpg.tiled-project` はゲームのデータから自動で作っています。`go run ./tools/update` で作り直す)
- ❌ 同じマップを2台以上で同時に直す
