# マップオブジェクト プロパティ設定 完全ガイド

このゲームのマップは **Tiled Map Editor** で作成した `.tmj` ファイル(`assets/maps/*.tmj`)です。
「マップエディタで設定するプロパティ」とは、Tiledの**オブジェクトのカスタムプロパティ(Custom Properties)**のことです。

> ⚠️ 重要: プロパティの**名前**は大文字小文字を区別しません(`targetMap`でも`targetmap`でも同じ)。
> しかし、プロパティの**値**(アイテムID、鍵の名前、スポーン地点名など)は大文字小文字も含めて完全一致で照合されます。
> 存在しない値を指定してもエラーにはならず、「何も起きない」形で静かに失敗するので、名前の綴りミスに注意してください。

イベントは、レイヤー名が **`events`で始まる**オブジェクトレイヤー(objectgroup)に配置したときだけ機能します。
当たり判定専用にしたい場合は、レイヤー名を **`collision`** にします(この中のオブジェクトはカスタムプロパティを一切読みません。四角形かポリゴンかで壁になるだけです)。

---

## 新しいマップを追加する手順(コード変更は不要)

タイルセット画像・マップ一覧(目的地案内やドアの経路探索の対象)はどちらも.tmjファイル自身の内容から自動的に読み取られる仕組みになっています。以下の手順だけで新マップを追加できます。**Goのコードには一切触りません。**

1. **Tiledで新しいマップを作る。** 既存の`.tmj`(`School_Map_1.tmj`など)を複製して土台にすると、タイルサイズ(32x32)やレイヤー構成を揃えやすいです。
2. **タイルセット画像を用意する。** 別の画像を使いたい場合は、Tiledの「タイルセット」パネルで参照先のPNGを差し替えるだけでOK(コピーしたPNGでも、全く新しい画像でも構いません)。保存時にTiledが.tmj内の`tilesets`→`image`のパスを自動的に書き換えるので、コード側の登録は不要です。
3. **マップ全体のプロパティを設定する(任意)。** 「1. マップ全体のプロパティ」の章にある `bgm` / `displayname` / `autoheal` をMap Propertiesに追加する。省略しても動作します(既定のBGM・パスそのものの表示名・自動回復なしになるだけ)。
4. **`events`レイヤーを作り、NPC・宝箱・ワープなどを配置する。** 2〜13章の各オブジェクトのプロパティ表に従って設定する。当たり判定が必要な場所には`collision`レイヤーも用意する。
5. **`.tmj`ファイルを`assets/maps/`に保存する。**
6. **既存マップとの間に必ずワープ(ドア)でリンクを作る。** 新マップ側のドアに`targetmap`(遷移先)、`targetpoint`(着地スポット名)を設定し、リンク元の既存マップ側にも新マップへ戻る/向かうドアを置く。
   - ⚠️ **これが唯一の必須ステップです。** マップ一覧はプレイ開始地点(`School_Map_1.tmj`)から`targetmap`をたどって自動的に集められるため、**どこからもワープでリンクされていない孤立したマップは、目的地案内・ドアの経路探索・鍵の対応チェックの対象に入りません**(直接そのマップへ遷移させるコードを書けば表示自体はされますが、通常の追加方法ではリンクを必ず作ってください)。
7. **ゲームを起動して確認する。** タイルセットが正しく表示されるか、ワープで行き来できるか、`bgm`/`displayname`/`autoheal`を設定した場合は意図通りに動くかを見る。

以前は「タイルセット画像を`assets_deferred.go`に登録」「マップを`map_registry.go`に登録」という2箇所のコード編集が必須でしたが、現在はこれらのファイル自体が存在しません(タイルセットは.tmjから動的読み込み、マップ一覧はワープリンクから自動探索する方式に変更されています)。

## 0. 共通のジオメトリ情報(Tiled標準の項目)

| 項目 | 説明 |
|---|---|
| ID(自動採番) | 宝箱の開封済み管理・レバー壁の解錠管理などの内部キーに使われます。**削除して作り直すとID変わるので既存セーブとの整合性が崩れる**ことがあります |
| X, Y, 幅, 高さ | 判定矩形として使われます |
| 名前(Name欄) | ワープの着地スポットを指すのに使います(後述) |
| ポリゴン | `collision`レイヤーでのみ意味を持ちます |

## 1. マップ全体のプロパティ

マップファイルを選択した状態(オブジェクトではなく、Tiledの **Map → Map Properties**)で設定します。

| プロパティ名 | 型 | 説明 | 値の例 | 未設定時 |
|---|---|---|---|---|
| `bgm` | string | このマップを歩行中に流すBGMのキー名 | 下表のいずれか | `field1`(コード既定値) |

**現在使える`bgm`キー一覧**(`audio.go`の`bgmByKey`):

| キー | 曲 |
|---|---|
| `title` | タイトル画面 |
| `field1`〜`field4` | フィールド曲1〜4 |
| `battle_normal` | 通常戦闘 |
| `battle_boss` | ボス戦闘 |
| `battle_lastboss` | ラスボス戦闘 |
| `ending` | エンディング |
| `talk_peaceful` / `talk_tense` / `talk_scary` / `talk_sad` | 会話専用BGM(平和/緊迫/恐怖/悲しみ) |

- 切り替わるタイミングは、そのマップに入る瞬間(ワープ移動時)で、画面の暗転と同じ長さでクロスフェードします(ドア移動は0.3秒など、遷移の種類によって変わります)。
- 会話中だけ一時的に別の曲を流したい場合は、マップ側の`bgm`ではなく**会話データ(JSON)側の`bgm`フィールド**で指定します。省略時はそれまで流れていた曲を継続し、会話終了後はマップの`bgm`に自動で戻ります。
- 一覧に無い新しい曲を使いたい場合は、mp3ファイルを`assets/bgm/`に置いた上で`audio.go`の`bgmByKey`にキーを追加するコード変更が必要です(Tiled側の設定だけでは新曲は追加できません)。

## 2. オブジェクトの種類早見表

すべて `type` プロパティ(+ 一部は `text` プロパティ)の組み合わせで種類が決まります。

| 種類 | `type` | `text` |
|---|---|---|
| NPC・看板・調べる(会話) | `event` | 上記以外の文字列 or 空 |
| アイテム宝箱 | `event` | `event_chest_<アイテムID>` |
| 鍵入り宝箱 | `event` | `event_chest_key_<鍵の名前>` |
| 壁(鍵式 / レバー式) | `event` | `event_wall` |
| レバー | `event` | `event_lever` |
| 押せるブロック | `event` | `event_block` |
| ブロック設置スポット | `event` | `event_blockspot` |
| ブロックドア | `event` | `event_blockdoor` |
| トリガー(自動演出・ボス戦導入) | `trigger` | (セリフ本文) |
| ボスシンボル | `boss` | 不問(`bossid`必須) |
| 雑魚敵エンカウントエリア | `enemy` | 出現する敵名リスト |
| 暗闇エリア | `darkness` | 不問 |
| ワープ/ドア | 不問 | 不問(`targetmap`プロパティの有無で判定) |
| スポーン地点(ワープ着地点) | 不問 | 不問(**オブジェクトの「名前」欄**で判定) |

## 3. NPC・看板・調べる(会話イベント)

`type = event`、かつ下記の特殊`text`のいずれにも該当しないもの。

| プロパティ名 | 型 | 説明 | 値の例・取りうる値 | 未設定時 |
|---|---|---|---|---|
| `type` | string | 種別 | `event`(固定・必須) | ― |
| `text` | string | セリフ本文、または特殊指定 | ① 空文字 → 固定文言「調べるとなにかあるかもしれない」<br>② 直書きのセリフ(`｜`で区切ると複数ページ)<br>③ `event_story_<id>` → `assets/dialogues/story/`内の会話データを参照 | 空文字 |
| `repeattext` | string | 2回目以降(既読後)に表示するセリフ。**直書きセリフのときのみ**有効 | 任意文字列(`｜`区切り可) | 空(毎回`text`と同じセリフを繰り返す) |
| `objectiveid` | string | このイベントを「目的地」として案内表示に登録するID | 任意のID文字列 | 無指定なら目的地扱いされない |
| `objectiveorder` | int | 目的地としての達成順序(小さいほど先に案内される) | 任意の整数 | 0 |
| `bossid` | int | 指定すると目的地の達成条件が「会話した」ではなく「該当ボスを倒した」に変わる | 1〜4 | 無指定なら「一度会話した」が達成条件 |

## 4. 宝箱

### 4-1. アイテム宝箱

| プロパティ名 | 型 | 説明 | 値 |
|---|---|---|---|
| `type` | string | 種別 | `event`(固定・必須) |
| `text` | string | 中身のアイテム指定 | `event_chest_<アイテムID>`(例: `event_chest_potion`)。アイテムIDが見つからない場合は「何も入っていなかった」と表示される |

### 4-2. 鍵入り宝箱

| プロパティ名 | 型 | 説明 | 値 |
|---|---|---|---|
| `type` | string | 種別 | `event`(固定・必須) |
| `text` | string | 中身の鍵指定 | `event_chest_key_<鍵の名前>`(例: `event_chest_key_鍵a`)。この「鍵の名前」を壁の`keys`プロパティで参照する |

- 開封済みかどうかはセーブデータに永続化されます(マップ + オブジェクトIDで管理)。
- 宝箱は自動的に壁扱い(通行不可)になります。プレイヤーが近づいて決定キーを押すと開封します。

## 5. 壁(鍵式 / レバー式)

`type=event`, `text=event_wall` は共通。**`lever`プロパティの有無で種類が完全に分岐**します。

### 5-1. 鍵式の壁(`lever`プロパティを付けない)

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `keys` | string | 解錠に必要な鍵の名前(カンマ区切り、複数指定可・全部揃うまで開かない) | 例: `鍵a,鍵b` | 空(=鍵不要で誰でも開けられる) |

### 5-2. レバー式の壁(`lever`プロパティを付ける)

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `lever` | string | 連動させるレバーの`id`(下記6章参照) | レバー側と同じ文字列 | ― |
| `passable` | string | `false`にすると、レバーが上がっても**見た目だけ変わり、通行判定には影響しない**(装飾用) | `false` / それ以外 | 通行判定に影響する壁として扱われる |
| `img` | string | 開いたときに表示する絵を、`imgs`辞書のキー名で個別に差し替える | 任意のキー | 空(コード既定の開放画像を使用) |

> 鍵式は「セーブに解錠状態を記録」、レバー式は「対応レバーの状態を都度参照」という仕組みの違いがあります。
> したがって **`keys`と`lever`を同時に設定しても`keys`は無視されます**(レバー式が優先)。

---

## 6. レバー

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `type` | string | 種別 | `event`(固定・必須) | ― |
| `text` | string | 種別マーカー | `event_lever`(固定・必須) | ― |
| `id` | string | レバーの識別子。壁の`lever`プロパティから参照される | 任意文字列(例: `lever_a`) | **必ず設定してください**。空のままだと他の無名レバーと状態を共有してしまい誤動作します |
| `oneway` | string | `true`にすると一度上げたら二度と操作できない一方通行レバーになる | `true` / それ以外 | 何度でも上げ下げ可能 |

## 7. 押せるブロックパズル

3種類のオブジェクトを**同じ文字列ID**で結び付けて使います(Tiled上でのリンク機能ではなく、文字列の一致だけで判定されるので、綴りミスに注意)。

### 7-1. 押せるブロック本体

| プロパティ名 | 型 | 説明 | 値 |
|---|---|---|---|
| `type` | string | 種別 | `event`(固定・必須) |
| `text` | string | 種別マーカー | `event_block`(固定・必須) |
| `id` | string | ブロックの識別子(位置をセーブに保存するためのキー) | 任意文字列。**空だとこのブロックは生成されません** |

### 7-2. ブロック設置スポット

| プロパティ名 | 型 | 説明 | 値 |
|---|---|---|---|
| `type` | string | 種別 | `event`(固定・必須) |
| `text` | string | 種別マーカー | `event_blockspot`(固定・必須) |
| `id` | string | スポットの識別子。ブロックドアの`spots`から参照される | 任意文字列(必須) |

判定は座標の一致(誤差4px以内)で行われます。ブロックがそのスポット位置に来ているかどうかだけを見ています。

### 7-3. ブロックドア

| プロパティ名 | 型 | 説明 | 値 |
|---|---|---|---|
| `type` | string | 種別 | `event`(固定・必須) |
| `text` | string | 種別マーカー | `event_blockdoor`(固定・必須) |
| `spots` | string | 開放条件となるスポットIDのカンマ区切りリスト。**全部**にブロックが乗ると開放 | 例: `spot1,spot2`。空だと永久に開きません |

開放されるまでは壁として機能し、開放時に画面が揺れる演出が入ります。

## 8. トリガー(自動演出・カットシーン・ボス戦導入)

プレイヤーが**通過した**瞬間に発火します(静止して重なっただけでは発火しません)。

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `type` | string | 種別 | `trigger`(固定・必須) | ― |
| `text` | string | 発火時のセリフ本文(直書き、または`event_story_<id>`参照) | 任意文字列 | ― |
| `bossid` | int | 指定するとボス戦導入トリガーになる。専用のボスセリフ(`assets/dialogues/boss_<番号>.json`)を自動的に使い、末尾にバトル開始処理が付く | 1〜4 | 無指定なら通常の一回きり演出 |
| `instant` | bool | `true`なら自動移動を飛ばして即座に暗転→セリフ表示 | `true` / `false` | `false` |
| `route` | string | 発火時にプレイヤーを自動移動させるルート。`down/left/right/up` + 距離(ピクセル)をカンマ区切りで連結 | 例: `up120` / `up224,right64` | 空(=`instant`と同じ扱いで、その場で暗転) |

**発火可否のルール:**
- `bossid`が**無い**トリガー → 一度発火したら、そのセーブデータでは二度と発火しません。
- `bossid`が**ある**トリガー → 対応するボスを既に倒していれば、そもそも判定自体スキップ(何度でも素通りできる)。まだ倒していなければ何度でも発火してボス戦セリフを表示します(この場合`text`は使われず、ボス専用セリフに差し替わります)。

## 9. ボスシンボル(フィールド上に立つ敵)

マップ読み込み時に一度だけ判定されます(倒した後は再読み込みしても出現しません)。

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `type` | string | 種別 | `boss`(固定・必須) | ― |
| `bossid` | int | ボス番号。スプライトと撃破フラグの両方に使われる | 1〜4 | **このプロパティが無いとオブジェクト自体が無視されます(必須)** |
| `objectiveid` | string | 目的地登録用(3章と共通の仕組み) | 任意ID | 無指定なら目的地扱いされない |

## 10. 雑魚敵エンカウントエリア

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `type` | string | 種別 | `enemy`(固定・必須) | ― |
| `text` | string | このエリアで出現しうる敵名(カンマ区切りで複数指定可、抽選で選ばれる) | 例: `フリーザ,セル` | ― |
| `maxcount` | int | 1回のエンカウントで同時に出現する敵の数上限 | 1〜4(最大4体という内部上限あり) | 1 |

プレイヤーがこのエリア内を歩くほど遭遇率が上がっていく仕組みです(32px歩くごとに確率上昇)。

## 11. 暗闇エリア

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `type` | string | 種別 | `darkness`(固定・必須) | ― |
| `lever` | string | 指定したレバーが上がっている間だけ暗闇を解除する | レバーの`id` | 空(=常に暗闇が有効) |

光の届く範囲(半径)はコード側の固定値(110px)で、プロパティでは調整できません。

## 12. ワープ / ドア

`type`プロパティは不要です。**`targetmap`プロパティさえあればワープとして機能**します。

| プロパティ名 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| `targetmap` | string | 遷移先マップのファイルパス | 例: `assets/maps/School_Map_1.tmj` | 空だとワープとして機能しません(必須) |
| `targetpoint` | string | 遷移先マップ内の**スポーン地点オブジェクトの「名前」欄**と一致させる文字列 | 遷移先マップに存在するオブジェクト名(例: `1階`) | 一致するものが無いと、既定の座標(190, 320)に飛ばされてしまう(エラーにはならず気づきにくいので要注意) |
| `requireboss` | int | 指定したボスを倒すまでこのドアが反応しない(通行止め) | 1〜4程度 | 無指定なら制限なし |

プレイヤーがこの矩形に**触れるだけ**で「▼ 進む」と表示され、決定キーで画面が切り替わります(フェード時間0.3秒)。
また、このプロパティはマップ同士のつながりを自動解析して案内矢印を出す機能にも使われます。

---

## 13. スポーン地点(ワープの着地点)

専用の`type`はありません。**Tiledのオブジェクトの「名前」欄**に、着地点として参照させたい名前を入れるだけです。

| 項目 | 型 | 説明 | 値 | 未設定時 |
|---|---|---|---|---|
| 名前(Name欄) | string | ワープ元の`targetpoint`と一致させる名前 | 任意文字列(例: `1階`, `start_point`) | 空だと絶対に一致しません(必須) |
| `dir` | int | スポーン時にプレイヤーが向く方向 | `0`=下, `1`=左, `2`=右, `3`=上 | 直前の向きを維持 |

---

## 14. 当たり判定専用レイヤー(`collision`)

レイヤー名を **`collision`** にした objectgroup 内のオブジェクトは、カスタムプロパティを一切読みません。

| 形状 | 説明 |
|---|---|
| 四角形(ポリゴンなし) | X, Y, 幅, 高さそのままを壁として登録 |
| ポリゴン | 多角形の当たり判定として登録(斜めの壁などに便利) |

---

## 15. プロパティ間の依存関係まとめ(チェックリスト)

- [ ] `type=event`の中で種類を分けているのは`text`の値。**固定文字列(`event_wall`など)は綴りを一字一句正確に**。
- [ ] 壁の`lever`プロパティは「**有る/無い**」で鍵式・レバー式が完全に切り替わる。両方の設定を混在させない。
- [ ] `passable`は**レバー式の壁でしか意味を持たない**(鍵式壁に付けても無視される)。
- [ ] ブロックパズルの`id`/`spots`は**文字列の完全一致**でしか結び付かない。Tiled上に矢印やリンクは無いので、命名ルールを決めて統一する(例: `spot1`,`spot2`,`block1`)。
- [ ] トリガーの`bossid`の有無で「何度でも通れる(撃破後)/一度きり」の挙動が変わる。ボス戦導入トリガーは`text`を書いても無視される(専用セリフに差し替わるため)。
- [ ] `instant=true`、または`route`を空にすると、自動移動しないその場演出になる。
- [ ] `objectiveid` / `objectiveorder` / `bossid` は、NPC・トリガー・ボスシンボルいずれにも後付けできる横断的なプロパティ。`bossid`があれば目的地達成条件が自動的に「ボス撃破」に変わる。
- [ ] ワープの`targetpoint`は着地点オブジェクトの「名前」欄と**完全一致**させる。一致しないと気づかないまま既定座標に飛ばされる。
- [ ] マップ全体の`bgm`はオブジェクトではなくマップ自体に設定する。
