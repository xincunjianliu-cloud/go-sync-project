# マップのしかけ(オブジェクト)の作り方

このゲームのマップは、**Tiled** というソフトで作った `.tmj` ファイルです(`assets/maps/` に入っています)。
この資料では、マップに「宝箱」「ドア」「敵の出る場所」などの**しかけ**を置く方法を説明します。

---

## はじめに:3つの基本

### ① マップは「タイル」と「オブジェクト」でできている

| | 何か | たとえると |
|---|---|---|
| **タイル** | 床・壁・水などの**見た目** | 塗り絵の色 |
| **オブジェクト** | Tiledで置く**四角い「しかけ」** | 塗り絵の上に貼る付箋 |

オブジェクトは、四角を置いただけでは何も起きません。**名札(カスタムプロパティ)** を付けると、その名札に合わせたしかけになります。

### ② 名札の付け方(Tiledの操作)

1. オブジェクトを選ぶ
2. 左の「プロパティ」パネルの下にある **「+」** を押す
3. 名札の名前(例: `type`)を入れ、種類は **string(文字)** を選ぶ
   - 種類は **string のままで大丈夫**です。表の「種類」が bool や int の名札でも、`true` や `3` と文字で書けば同じように動きます(bool / int を選んでもかまいません)
4. 値(例: `event`)を入れる

### ③ 大事な決まり

- **名札の名前**は、大文字と小文字を区別しません(`targetMap` と `targetmap` は同じ扱いです)。
- **名札の値**は、大文字と小文字も含めて**1文字も違わず**書きます(アイテムの名前・鍵の名前・着地点の名前など)。
- **書き間違えても、エラーは出ません。「何も起きない」だけです。** 動かないときは、まず綴りを確認してください。
  - ドアの行き先とレバーの書き間違いは、`go test ./...` で見つけられます。

## レイヤーの決まり

レイヤーは「重ねる透明なシート」です。名前によって役割が決まります。

| レイヤー名 | 種類 | 役割 |
|---|---|---|
| `events`(`events` で始まる名前ならよい。例: `events2`) | オブジェクト | **しかけは全部ここに置く**。ほかのレイヤーに置いたしかけは動きません |
| `collision` | オブジェクト | **通れない場所**。四角や多角形を置くだけで、名札は要りません |
| `player` | オブジェクト | 何も置かない。**このレイヤーの位置が主人公を描く重なり順**になります(上のレイヤーのタイルは主人公より手前に描かれます) |
| `kabe` | タイル | ここに置いたタイルは**通れない** |
| そのほかの名前 | タイル | 見た目だけ(通れる) |

**タイルレイヤーに付けられる名札**

| 名札 | 種類 | 意味 |
|---|---|---|
| `leveropen` | bool | `true` にすると、このレイヤーの絵は**レバー壁が開いているときだけ**現れます(詳しくは「レバー」の章) |

**注意:Tiledでの表示・非表示(目のアイコン)は、ゲームには関係ありません。** 非表示にしたレイヤーも、ゲームでは描かれます。

**タイルに付ける名札(タイルセット側)**
タイルセットの編集画面で、タイルに名札 `wall`(bool)=`true` を付けると、そのタイルは**どのレイヤーに置いても通れなく**なります。
ただし、マップ全体に背景として敷くタイル(例: `water_b` の水)には付けないでください。その上の床まで通れなくなります。

## 1. 話しかける・調べる(NPC・看板)

決定キーで話しかけたり調べたりできるしかけです。

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `type` | string | `event` | (必須) |
| `text` | string | 下の3つのどれか | ①になる |
| `repeattext` | string | **2回目以降**に出すセリフ(`text` に直接セリフを書いたときだけ使えます) | 毎回同じセリフ |

**`text` の書き方**
- ① **空にする**:「調べるとなにかあるかもしれない」と出ます
- ② **セリフを直接書く**:`｜`(全角の縦棒)で区切ると、ページが分かれます
  - 例:`こんにちは｜今日はいい天気だね`
- ③ **`event_story_名前`**:`assets/dialogues/story/` にある会話データを使います(長い会話向け)

**目的地の案内に出したいとき**(画面に「次はここ」と出す機能)

| 名札 | 種類 | 書くこと |
|---|---|---|
| `objectiveid` | string | 目的地の名前(好きな名前でよい) |
| `objectiveorder` | int | 案内する順番。小さい数ほど先に案内されます(書かないと0) |
| `bossid` | int | 書くと「そのボスを倒したら次へ進む」になります。書かないと「1回話しかけたら次へ」 |

この3つは、トリガー(6章)やボス(7章)にも付けられます。

## 2. 宝箱

| 作りたいもの | `type` | `text` |
|---|---|---|
| アイテムの宝箱 | `event` | `event_chest_アイテムID`(例: `event_chest_potion`) |
| 鍵の宝箱 | `event` | `event_chest_key_鍵の名前`(例: `event_chest_key_鍵a`) |

- 宝箱は通れません。近づいて決定キーで開けます。
- 開けたかどうかはセーブに残ります。
- アイテムIDを間違えると「何も入っていなかった」と出ます。
- 鍵の名前は、3章の壁の `keys` に書く名前と同じにします。

## 3. 鍵で開く壁

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `type` | string | `event` | (必須) |
| `text` | string | `event_wall` | (必須) |
| `keys` | string | 開けるのに必要な鍵の名前。カンマで区切ると複数必要になります(例: `鍵a,鍵b`) | 鍵なしで開く |

- 開けたかどうかはセーブに残ります。
- `lever` の名札を付けると、4章の「レバーで開く壁」になります(`keys` は無視されます)。

## 4. レバーと、レバーで開く壁

### レバー

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `type` | string | `event` | (必須) |
| `text` | string | `event_lever` | (必須) |
| `id` | string | レバーの名前(例: `lever_a`) | **必ず書く**。空のレバー同士が連動して、おかしくなります |
| `oneway` | string | `true` にすると、一度上げたら戻せない | 何度でも上げ下げできる |

### レバーで開く壁

**`lever` の名札だけで作れます**(`type` と `text` は要りません)。

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `lever` | string | つなげるレバーの `id`(例: `lever_a`) | (必須) |
| `passable` | string | `false` と書いたときだけ、**レバーを上げても通れない**(見た目だけ変わる) | **レバーを上げると通れる** |
| `img` | string | 開いたときの絵を、場所ごとに変えたいときに使う(下の「詳しく」を参照) | 既定の絵 |

**`passable` のまとめ**
- **何も書かない** → レバーを上げると**通れる**(ふつうはこれ)
- `true` と書く → 何も書かないのと同じ。レバーを上げると**通れる**
- `false` と書く → レバーを上げても**通れない**。見た目だけ変わる

| | レバーが下がっている | レバーを上げた |
|---|---|---|
| 普通のレバー壁 | 通れない | **通れる** |
| `passable=false` の壁 | 通れない | 通れないまま、**見た目だけ変わる** |

### 開いたときの見た目(どちらか)

**A. タイルで描く(おすすめ)**
1. タイルレイヤーを1枚作り、名札 `leveropen`(bool)=`true` を付ける
2. そのレイヤーの、レバー壁と同じ範囲に絵を描く
3. その絵は**レバーを上げたときだけ**現れる

例:`water_b` の `机` レイヤー。レバーを上げると、水の上に机の橋が現れて渡れます。

**B. 何も描かない**
開いたとき、`lever_wall_open.png`(机の絵)が壁の範囲に敷き詰められます。
`passable=false` の壁なら `lever_wall_open_deco.png`(水の絵)になります。

### 例:水と机の橋

| 場所 | 作り方 |
|---|---|
| 机の橋(レバーで渡れる) | レバー壁(`lever=lever_a`)+ `leveropen` レイヤーに机 |
| ただの水(ずっと通れない) | 水を描き、`collision` に四角を置く |
| レバーで見た目が変わる水(ずっと通れない) | レバー壁に `passable=false` + 別の `leveropen` レイヤーに「変わった後の水」 |

<details>
<summary>詳しく:<code>img</code> で場所ごとに絵を変える(プログラムの変更が必要)</summary>

1. `assets/images/field/lever_wall_open_名前.png` を作る(`passable=false` の壁なら `lever_wall_open_deco_名前.png`)
2. `assets_deferred.go` に1行登録する
3. 壁に `img`=名前 を付ける

ふつうはAの「タイルで描く」方法のほうが簡単です。
</details>

## 5. 押せるブロックのパズル

ブロックを押して決まった場所に乗せると、扉が開くパズルです。
3つのしかけを、**同じ名前で結びつけて**使います。

| しかけ | `type` | `text` | ほかの名札 |
|---|---|---|---|
| 押すブロック | `event` | `event_block` | `id`=ブロックの名前(**空だとブロックが出ません**) |
| 乗せる場所 | `event` | `event_blockspot` | `id`=場所の名前 |
| 開く扉 | `event` | `event_blockdoor` | `spots`=乗せる場所の `id`。カンマで区切ると「全部に乗せたら開く」(**空だと開きません**) |

- 扉は開くまで通れません。開くときに画面が揺れます。
- ブロックの位置はセーブに残ります。
- ブロックが乗せる場所とほぼ同じ位置(4ピクセル以内)に来ると「乗った」と判定されます。

```
[扉]          type=event  text=event_blockdoor  spots=spot1,spot2
[ブロック1]   type=event  text=event_block      id=block1
[ブロック2]   type=event  text=event_block      id=block2
[乗せる場所1] type=event  text=event_blockspot  id=spot1
[乗せる場所2] type=event  text=event_blockspot  id=spot2
```

## 6. 通ると起きるイベント(トリガー)

主人公が四角を**通り抜けた**ときに起きます(重なって止まっているだけでは起きません)。

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `type` | string | `trigger` | (必須) |
| `text` | string | セリフ(書き方は1章と同じ) | ― |
| `route` | string | 起きたときに主人公を自動で歩かせる道順。`up`/`down`/`left`/`right` + 距離(ピクセル)を、カンマでつなぐ(例: `up120` / `up224,right64`) | 歩かずにその場で始まる |
| `instant` | bool | `true` にすると、歩かずにすぐ暗転してセリフ | `false` |
| `bossid` | int | 書くと**ボス戦の入口**になる(下を参照) | 普通のイベント |

**起きる回数**
- `bossid` が**無い**:そのセーブで**1回だけ**
- `bossid` が**ある**:そのボスを倒すまで、通るたびに起きる。倒した後は素通りできる
  - セリフは `assets/dialogues/boss_番号.json` が使われ、最後に戦闘が始まります(`text` は使われません)

```
[ボス戦の入口]  type=trigger  bossid=1  route=up120
```

## 7. フィールドに立つボス

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `type` | string | `boss` | (必須) |
| `bossid` | int | ボスの番号(1〜4)。見た目と「倒したか」の記録に使います | **無いと出ません** |
| `objectiveid` | string | 目的地の案内に出す名前(1章と同じ) | 案内に出ない |

倒したボスは、もう一度そのマップに来ても出ません。
6章のトリガーと組み合わせて、「近づくと会話→戦闘」にするのが基本です。

## 8. 雑魚敵が出る場所

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `type` | string | `enemy` | (必須) |
| `text` | string | 出る敵の名前。カンマで区切ると、その中から選ばれます(例: `スライム1,オーク1`) | ― |
| `maxcount` | int | 一度に出る数の上限(1〜4) | 1 |

- 敵の名前は `tools/genstats/seed/enemies.csv` の `Name` 列と同じにします。
- 四角の中を歩くほど、敵に出会いやすくなります(32ピクセル歩くごとに確率が上がります)。

|---|---|---|---|
| `type` | string | `darkness` | (必須) |
| `lever` | string | そのレバーを上げている間は明るくなる | ずっと暗い |

## 10. ドア(ほかのマップへ移動)

`type` は要りません。**`targetmap` があればドアになります。**

| 名札 | 種類 | 書くこと | この名札を付けなかったとき |
|---|---|---|---|
| `targetmap` | string | 行き先のマップ(例: `assets/maps/school_1.tmj`) | ドアにならない |
| `targetpoint` | string | 行き先のマップの**着地点の名前**(11章) | 決まった位置(190, 320)に飛ばされる |
| `requireboss` | int | そのボス(番号)を倒すまで通れない | いつでも通れる |

- 四角に触れると「▼ 進む」と出て、決定キーで移動します。
- 行き先のマップと着地点が無いときは、`go test` で止まります。
- ドアのつながりは、目的地の案内で「どのドアへ向かえばよいか」を出すのにも使われます。

## 11. 着地点(ドアで来たときに立つ場所)

`type` も名札も要りません。**オブジェクトの「名前」欄に名前を書くだけ**です。

| 項目 | 書くこと |
|---|---|
| 名前欄 | ドアの `targetpoint` と同じ名前(例: `入口`)。日本語でもよい |
| `dir`(int、なくてもよい) | 着いたときの向き。`0`=下、`1`=左、`2`=右、`3`=上 |

- 1つのマップの中で、同じ名前を2つ使わないでください。
- 開始マップ(`school_1.tmj`)の `start_point` は消さないでください(ニューゲームの開始位置です)。

```
[school_1.tmj のドア]    targetmap=assets/maps/water_b.tmj  targetpoint=梯子3
[water_b.tmj の着地点]   名前欄=梯子3
```

## 12. マップ全体の設定

オブジェクトではなく、**マップそのもの**に付けます(Tiledの「マップ」→「マッププロパティ」)。どれも付けなくても動きます。

| 名札 | 種類 | 意味 | 例 | この名札を付けなかったとき |
|---|---|---|---|---|
| `displayname` | string | 地名。**ドアで入ったとき・セーブを読み込んだとき・ニューゲームのとき**に左上に出ます(戦闘から戻ったときは出ません)。セーブ画面にも出ます | `学校` | ファイルの場所がそのまま出る |
| `bgm` | string | 歩いているときの曲(下の表から選ぶ) | `field1` | `field1` |
| `battlebg` | string | 戦闘の背景。`assets/images/battle/bg/名前.png` を使います | `school` | `battle_bg.png` |
| `autoheal` | bool | `true` にすると、**マップに入るたびに**(ドア・セーブの読み込み・ニューゲーム)全回復します(戦闘から戻ったときは回復しません) | `true` | 回復しない |

**使える曲(`bgm`)**

| 名前 | 曲 |
|---|---|
| `field1`〜`field4` | フィールド曲1〜4 |
| `title` | タイトル |
| `battle_normal` / `battle_boss` / `battle_lastboss` | 戦闘 / ボス戦 / ラスボス戦 |
| `ending` | エンディング |
| `talk_peaceful` / `talk_tense` / `talk_scary` / `talk_sad` | 会話用(平和 / 緊迫 / 恐怖 / 悲しみ) |

- 曲はマップに入った瞬間に切り替わります。
- 会話の間だけ曲を変えたいときは、会話データ側の `bgm` で指定します。
- 新しい曲を足すには、プログラムの変更が必要です(`audio.go` の `bgmByKey`)。

**戦闘の背景(`battlebg`)**
- 今ある背景は `school` だけです。
- 新しい背景は、PNGを `assets/images/battle/bg/` に置き、その名前(`.png` は付けない)を書くだけで使えます。
- 名前を間違えると、既定の背景になります。
- 似た場所のマップでは、同じ背景を使い回します。

## 13. 新しいマップを追加する手順

プログラムの変更は要りません。

1. **Tiledで新しいマップを作る**
   - タイルの大きさは 32×32 にする(既存のマップをコピーして作ると楽です)
   - 保存先は `assets/maps/` にする。**必ずこのプロジェクトのフォルダの中で作る**(外で作ると絵の場所がずれます)
   - **ファイル名は英小文字・数字・`_` だけにする**(例: `dungeon_a.tmj`)。日本語の地名は `displayname` で付けます
2. **タイルセットを付ける**
   - 「タイルセット」パネルの「**外部タイルセットを追加**」から、`assets/tilesets/` の `.tsx` を選ぶ
   - 新しい絵を使うときは、`docs/タイルセット運用ルール.md` を見てください
3. **絵を描き、しかけを置く**(この資料の1〜11章)
4. **ほかのマップとドアでつなぐ(必須)**
   - 新しいマップにドアと着地点を置き、既存のマップ側にも新しいマップへ入るドアを置く
   - ゲームは開始マップからドアをたどってマップを見つけます。**どこからもつながっていないマップは `go test` で止まります**
5. **確認する**
   ```
   go test ./...
   ```
   次のミスを見つけてくれます。GitHubに上げたときも同じテストが走り、失敗すると公開されません。
   - タイルセットの付け方の間違い、絵が見つからない
   - ドアの行き先のマップや着地点が無い、どこからもつながっていないマップがある
   - レバー壁がつながるレバーが無い
6. **ゲームを起動して、行き来できるか確かめる**

### 公開した後の注意

- **マップのファイル名は変えない。** ファイル名はセーブに残るので、変えると古いセーブが読めなくなります。
  どうしても変えるときは `save_migrate.go` の `renamedMapPaths` に「古い名前 → 新しい名前」を足します(消したマップは `removedMapPaths`)。
- **オブジェクトを消して作り直さない。** 宝箱などはオブジェクトの番号(ID)でセーブに記録されるので、作り直すと開けた記録がずれることがあります。

## 14. 別のPCで作ったマップをメールで送る

### 準備(別のPCで、最初の1回だけ)

1. `https://github.com/xincunjianliu-cloud/go-sync-project` を開く
2. 緑の「**Code**」→「**Download ZIP**」でダウンロードし、右クリック →「すべて展開」
3. 展開した `go-sync-project-main` フォルダの中で作業する(中の形はこのPCと同じです)

このPCで新しいタイル画像を足したときは、準備をやり直してください。

### 送る(別のPCで)

1. 13章の手順でマップを作る。**既存のマップ(`school_1.tmj` など)は直さない**
2. メールに添付する
   - 作ったマップの `.tmj`
   - 新しいタイルセットを作ったときだけ、その `.tsx` と `.png`
3. 本文に書く
   - 既存のマップの**どこから入るか**(例:「`school_1` の右上の階段から」)
   - 新しいマップの**着地点の名前**(例:「`入口`」)

### 受け取る(このPC)

1. 添付ファイルをダウンロードフォルダに保存する
2. Claudeに「マップが届いた」と伝える(ファイルの置き場所、既存のマップ側のドア、テスト、GitHubへのアップロードをやってくれます)

自分でやるときは、次の場所にコピーして、既存のマップにドアを足し、`go test ./...` を実行します。

| ファイル | コピー先 |
|---|---|
| `.tmj` | `assets/maps/` |
| `.tsx` | `assets/tilesets/` |
| `.png` | `assets/images/tiles/` |

## 15. うまく動かないときのチェックリスト

- [ ] しかけを `events` で始まる名前のレイヤーに置いたか
- [ ] `event_wall` などの決まった言葉の綴りは合っているか
- [ ] つながる相手と名前が**1文字も違わず**同じか(ドアの `targetpoint` と着地点の名前、壁の `lever` とレバーの `id`、ブロックの `spots` と乗せる場所の `id`、宝箱の鍵の名前と壁の `keys`)

- [ ] ボスに `bossid` を付けたか
- [ ] 名札の名前の綴りは合っているか(例: `autoheal` を `autoheel` にしていないか)
- [ ] マップ全体の設定(`bgm` など)を、オブジェクトではなくマップに付けたか
- [ ] `battlebg` の名前は、背景画像のファイル名と同じか
- [ ] `go test ./...` は通るか
