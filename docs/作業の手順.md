# 作業の手順

前の「ルーティン」の代わりのメモです。

---

## いつもの流れ(GitHub Desktop)

**作業を始めるとき**
1. Tiledを閉じる(開いたままだと、ほかのPCの変更を消してしまうことがある)
2. GitHub Desktop の「**Fetch origin**」を押す
3. ボタンが「**Pull origin**」に変わったら、それも押す(ほかのPCの変更が入る)

**作業が終わったとき**
1. GitHub Desktop の左下の欄に、何をしたか一言書く(例:「学校のマップを直した」)
2. 「**Commit to main**」を押す
3. 「**Push origin**」を押す(ほかのPCに届く。Web版も自動で公開される)

---

## シナリオ(会話)を取り込む

スプレッドシートで会話を直したあとにやる。

**1. 会話を取り込む**
```
go run ./tools/dialoguegen
```
→ `wrote ...` という行がいくつか出れば成功。

**2. Tiledの一覧を作り直す**(会話の名前が増えたときにTiledで選べるようにする)
```
$env:UPDATE_TILED_PROJECT=1; go test -run TestTiledProjectUpToDate .; Remove-Item Env:UPDATE_TILED_PROJECT
```
→ `ok` と出れば成功。

**3. まちがいが無いか調べる**
```
go test ./...
```
→ 全部の行が `ok` か `?` なら成功。

**4. GitHub Desktop で Commit → Push**

---

## ステータス(強さ)を取り込む

スプレッドシートで強さを直したあとにやる。
やり方はシナリオと同じで、**1つ目のコマンドだけ**ちがう。

**1. 強さを取り込む**
```
go run ./tools/genstats
```
→ `wrote stats_generated.go` と出れば成功。

**2. Tiledの一覧を作り直す**(シナリオの2と同じ)
```
$env:UPDATE_TILED_PROJECT=1; go test -run TestTiledProjectUpToDate .; Remove-Item Env:UPDATE_TILED_PROJECT
```

**3. まちがいが無いか調べる**(シナリオの3と同じ)
```
go test ./...
```

**4. GitHub Desktop で Commit → Push**

## ゲームを試す

- **今のマップから遊ぶ**:Tiledでマップを開いて **F5**
- **最初から遊ぶ**:コマンド `go run .`

---

## Web版の公開

**何もしなくていい。** Push すると自動で公開される。
失敗したときは、GitHubに登録したメールアドレスに「失敗しました」というメールが来る。

---

## うまくいかないとき

- **`FAIL` と出た**:その少し上に、何がまちがっているかが日本語で出ている。スプレッドシートやマップを直して、同じコマンドをもう一度打つ
- **取り込んだのをやめたい**:GitHub Desktop で、変わったファイルを右クリック →「**Discard changes**」。Commit する前なら元に戻る
- **失敗のメールが来た**:メールのリンクを開くと、赤い×の所に理由が出ている。直してもう一度 Push
