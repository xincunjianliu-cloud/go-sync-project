# 作業の手順

前の「ルーティン」の代わりです。GitHub Desktop でやり取りし、取り込みは自分でコマンドを打つ前提で書いています。

---

## 0. PowerShellを開く(コマンドを打つとき毎回)

1. エクスプローラーで作業フォルダを開く(メインPCは `rpg`、ほかのPCは `go-sync-project`)
2. 上のアドレス欄に `powershell` と打って Enter
3. 開いた黒い画面にコマンドを1行ずつ貼り付けて Enter

---

## 1. ほかのPCとのやり取り(コマンド不要)

| いつ | GitHub Desktopで |
|---|---|
| 作業の前 | 「Fetch origin」→「Pull origin」 |
| 作業の後 | 下に一言書いて「Commit to main」→「Push origin」 |

- Pullする前に、Tiledで開いているマップは保存して閉じる
- 同じマップを2台以上で同時に直さない
- くわしくは [マップ作りガイド](マップ作りガイド.md) の2章

---

## 2. シナリオ(会話)を取り込む

スプレッドシートを直したら、Pullしてから順に打つ:

```
go run ./tools/dialoguegen
```
```
$env:UPDATE_TILED_PROJECT=1; go test -run TestTiledProjectUpToDate .; Remove-Item Env:UPDATE_TILED_PROJECT
```
```
go test ./...
```

| コマンド | やること |
|---|---|
| 1つ目 | スプレッドシートの会話をゲームに取り込む |
| 2つ目 | Tiledの「会話データ」などの一覧を作り直す |
| 3つ目 | チェック |

最後に `ok` と出たら、GitHub Desktop で Commit → Push。

- 会話の書き方は [シナリオ記述ルール](シナリオ記述ルール.md)
- 取り込んだファイル(`assets\dialogues\…`)は直接いじらない。直すのは必ずスプレッドシート

---

## 3. ステータス(強さ)を取り込む

スプレッドシートを直したら、Pullしてから順に打つ:

```
go run ./tools/genstats
```
```
$env:UPDATE_TILED_PROJECT=1; go test -run TestTiledProjectUpToDate .; Remove-Item Env:UPDATE_TILED_PROJECT
```
```
go test ./...
```

1つ目で強さを取り込み、2つ目でTiledの「敵」の一覧を作り直し、3つ目でチェック。最後に `ok` と出たら Commit → Push。

### 敵の技(Skills列)

敵のシートとボスのシートの一番右(17列目)に **`Skills`** という列がいる。**この列が無いまま取り込むと、敵の技がすべて消える。** 技を2つ書くときはカンマでつなぐ(スペースは入れない)。

| 敵 | Skills |
|---|---|
| スライム1〜3 | `tackle` |
| ゴブリン1〜3 | `club_smash` |
| オーク1〜3 | `heavy_slam` |
| コボルト1〜3、ワイルドウルフ1〜3 | `bite` |
| リザードマン1〜3 | `tail_sweep` |
| ジャイアントバット1〜3 | `supersonic` |
| マッドプラント1〜3 | `spore_cloud` |
| ストーンゴーレム1〜3 | `rock_punch` |
| スケルトン1〜3 | `bone_cleave` |

| ボス | Skills |
|---|---|
| boss_1 | `flame_burst,crushing_blow` |
| boss_2 | `thunder_bolt,crushing_blow` |
| boss_3 | `ice_breath,crushing_blow` |
| boss_4 | `wind_slash,flame_burst` |

使える技の名前は `enemy_skill.go` に書いてある。無い名前を書くと、1つ目のコマンドがエラーで止まる。

## 5. Web版を公開する

**コマンドは要らない。** Pushすると、GitHubがチェック → Web版の作成 → 公開まで自動でやる。

- 止まったときは、GitHubの登録メールアドレスに「失敗しました」というメールが届く
- メールのリンク先で赤い×の行を開くと、どこが悪いか書いてある。直してもう一度Push

---

## 6. エラーが出たとき

- `go test ./...` で `FAIL` と出たら、その少し上に日本語で原因が出ている(例:「敵 ○○ がいません」)。スプレッドシートかマップを直して、同じコマンドをもう一度打つ
- 取り込みを途中でやめたいときは、GitHub Desktop で変更されたファイルを右クリック →「Discard changes」で元に戻せる(Commitする前なら)
